# Audit of the proposed stack additions

Research and retrieval date: **19 October 2026**. Baseline: local revision `b6fa825`.
This is an adoption audit, not an installation record. None of the newly listed candidates
was installed or granted account access by this audit. The previously selected additions
are delivered separately in [the implementation guide](../picked-stack-additions.md).

## What is worth trying first

The list contains real opportunities. The most promising changes add visual evidence,
consistent document extraction, better design references, or more precise code navigation.
Another general agent framework is a larger commitment with less demonstrated benefit here.

| Order | Bounded next step | What would justify keeping it |
| --- | --- | --- |
| 1 | Trial `/watch` on a short local screen recording, using frames and existing captions/transcripts. | Correct source-relative timestamps, readable frames, and a useful answer about something the transcript misses; no cloud call or new speech environment. |
| 2 | Trial AnyDoc's local CLI on representative office files and a text PDF. | Preserve expected headings, tables, notes and reading order better than the current extraction path. A scanned PDF must stop locally rather than silently upload. |
| 3 | Compare one small frontend skill against the current approach on one real brief. Start with official `frontend-design`; use UI UX Pro Max as an optional lookup reference. | Better result at desktop and phone sizes, keyboard usability and fewer corrections. Taste is an alternative experiment with a larger published time/context budget. |
| 4 | Trial Repomix for an explicitly selected export and RTK OSS for selected verbose commands. | A useful, inspectable export; shorter command output without losing failures, exit codes or needed diagnostics. No automatic hooks initially. |
| 5 | Compare Graphify code-only analysis with Serena's narrow navigation tools on one real cross-file question. | Correct symbol/caller evidence and useful navigation, with measured indexing cost and stale-index detection. Do not install both permanently before comparing them. |
| 6 | On the next actual application-control gap, trial one CLI-Anything harness. | The installed application opens the resulting project and renders the intended output; a fake backend or mocked render does not qualify. |
| 7 | Consider exact-target Claude session messaging through the native mod API. | A requested message reaches the intended session, refusal/queue states are visible, and existing ownership/admission rules remain effective. |
| 8 | For a real connector gap, trial one Composio custom integration or a bounded Firecrawl retrieval route. | A missing workflow succeeds within a verified hard free limit and narrow account scope, with no paid provider fallback. |

These are recommendations for small trials, not claims that those trials have passed. OpenMontage's
stock-footage retrieval, VoiceStudio's dubbing/cloning, and OpenDesign's design-system material also
deserve focused evaluation when those workflows are requested; they are not interchangeable with
the local speech-editing tool just delivered.

## Evidence and decision rules

Local evidence came from `README.md`, `docs/decisions.md`, `refs/repos.json`, `config/mcp.json`,
the shared skill sources, the video template and command discovery. Current MCP configuration
contains Context7 and nar. FFmpeg, FFprobe, yt-dlp, Deno, Python, Node, gh and Playwright are
discoverable in this shell. Remotion is already used through shared project dependencies;
absence of a global `remotion` command is not absence of Remotion.

The stack already has worktrees, writer claims, native-worker admission, cross-vendor delegation,
checked checkpoints, HANDOFF files, quota observations, continuation checks, video review gates,
local transcription and a read-only native status mod pilot. Existing skills cover documents,
PDFs, presentations, spreadsheets, browser use and visualizations. A reference clone or catalog
entry does not mean its skills or runtime are activated.

Primary repositories and documentation linked in the tables were opened. Public GitHub API
metadata and README snapshots are retained under `~/.aos/research/stack-candidate-audit-20261019`.
The [source snapshot](2026-10-19-candidate-sources.md) records repository identity, licence metadata
and last-push observations. Last push is a maintenance signal, not proof of a release, review,
support quality or a passing test. Null/undetected licences remain unknown.

**Trial** means worth a bounded experiment; **conditional** needs a specific workload or unresolved
feasibility check; **keep** means already present or worth using as a reference; **defer** means
the integration cost or conflict outweighs demonstrated value today. Ambiguous names are evaluated
through the plausible primary matches below, without asserting which one the user meant.

No candidate's advertised speed, token savings, model quality or safety boundary was reproduced
locally. Documentation recipes and published CI are distinguished from a working installation on
this laptop. Existing subscriptions do not imply access to a third party's paid API.

## AnyDoc

[firecrawl/anydoc](https://github.com/firecrawl/anydoc), MIT, provides a common local Markdown
conversion path for office documents and text PDFs. Public npm metadata for `@firecrawl/anydoc`
version [`0.2.4`](https://registry.npmjs.org/@firecrawl/anydoc/0.2.4) includes a `win32-x64-msvc` optional binary package. This is better native Windows
distribution evidence than merely seeing a cross-platform claim; the binary was not downloaded.

**Trial the local CLI, not a hosted OCR default.** Compare real headings, table cells, slide notes,
equations and reading order against known expected content and the current document tools. The
upstream benchmark is not a result on this laptop. It does not replace document editing, rendering
or visual QA. Scanned/image-only PDFs return `NeedsOcr` locally. Opting into hosted OCR sends the
whole document; a free allowance does not make that local. Existing PDF/OCR alternatives should be
compared on the actual failing document before adding more extractors.

## Coverage and limitations

The spelling variants `claiude mem` and the second `headroom` refer back to the corresponding
Claude-mem and Headroom evaluations. Firecrawl's service and its MCP adapter were assessed separately.
Ambiguous labels include their plausible matches above or below; no exact user referent is claimed.

This audit ran public-source retrieval, repository metadata checks, local baseline inspection and
documentation consistency checks. It did not execute candidate installers, grant OAuth access,
download models/browsers, test new services or spend API credits. Therefore **trial** does not mean
approved for unrestricted activation. Existing project review requirements still apply when a later
change writes vendor configuration, the user PATH or consequential account/security settings.

The selected additions preceding this audit passed `aos test`: 526 tests under each required shell,
with no failures or skips. Their full bootstrap dry-run stalled in the existing model-sync stage
and was interrupted; it is not a successful preview. Candidate-audit changes are documentation only,
so the runtime suite is not being repeated for this report. See the implementation guide for exact
verification evidence and remaining activation/live-UI limits.
