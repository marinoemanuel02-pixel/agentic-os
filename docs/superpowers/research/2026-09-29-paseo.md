## Install on Windows and the daemon
- Official ways: the desktop app (NSIS, per-user, `Paseo-Setup-${version}-${arch}.exe`, x64/arm64, bundles
  the CLI and server; `README.md:72-76`, `packages/desktop/electron-builder.yml:82-100`) or the npm CLI
  `npm install -g @getpaseo/cli` (`README.md:80-85`). No winget/scoop/choco package (not found).
- The npm CLI runs the daemon with the current Node (`packages/cli/src/commands/daemon/local-daemon.ts:53-61`);
  the repo pins Node 22.20.0, no `engines` field (`.tool-versions:2`).
- Daemon: `paseo daemon start` (background, supervised), `run` (foreground), `stop|restart|status|reload`
  (`public-docs/cli.md:279-310`); the desktop app's managed daemon stops on quit unless "Keep daemon running
  after quit" (`packages/desktop/src/settings/desktop-settings.ts:37-40`). Start at login / Windows service: not found.
- State: `PASEO_HOME` = `%USERPROFILE%\.paseo` (`packages/server/src/server/paseo-home.ts:4-18`): config.json,
  daemon-keypair.json, daemon.log, agents/, projects/, plugins/, worktrees/, opencode-home/
  (`docs/data-model.md:46-70`). Desktop settings/logs under `%APPDATA%\Paseo` (`public-docs/troubleshooting.md:83`).
- Listens on 127.0.0.1:6767 (`packages/server/src/server/persisted-config.ts:343-353`).
- Windows: the daemon does not load a login shell's environment; agent CLIs must be on the PATH it started
  with; check with `paseo provider diagnostic <provider>` (`public-docs/troubleshooting.md:64-70`, `cli.md:26-36`).

## Pairing and remote access
- Relay off by default (`persisted-config.ts:350-352`). CLI: `paseo daemon pair --relay` enables it and prints
  the QR/link (`cli.md:371-377`); without `--relay` the code prints RELAY_DISABLED and exits 1
  (`packages/cli/src/commands/daemon/pair.ts:160-197`; the docs wrongly say it prompts).
- Phone: Add connection -> Scan QR / Paste link / Direct connection / Remote SSH (`packages/app/src/i18n/resources/en.ts:1645-1662`);
  Android from the Play Store (`sh.paseo`) or a GitHub APK; the F-Droid build cannot scan QR (`docs/android.md:145`).
- Relay `relay.paseo.sh:443`, end-to-end encrypted (NaCl box); the relay sees IPs, timing, sizes, session ids
  (`public-docs/security.md:24-53`). Treat the QR like a password (`security.md:53`). No telemetry (`README.md:48`).
- Optional password: `paseo daemon set-password` (bcrypt in config.json, restart) or `PASEO_PASSWORD`
  (`public-docs/configuration.md:167-197`). LAN direct connection needs `daemon.listen <ip>:6767` + restart;
  never bind 0.0.0.0 without a password (`security.md:69-71,149`).

## Providers
- Paseo runs the installed agent CLIs; their own configs, skills and MCP servers apply (`public-docs/providers.md:11-22`).
- Claude Code: Claude Agent SDK pointed at `claude` on PATH (`providers/claude/agent.ts:1706-1717,3284-3312`).
- Codex: `codex` on PATH, else the Store install; runs `codex app-server` (`codex-app-server-agent.ts:452-511,7107-7132`).
- OpenCode: `opencode` on PATH (Windows `.cmd` shim followed), `opencode serve` on 127.0.0.1 with cwd
  `$PASEO_HOME/opencode-home`; Paseo merges its own plugin into `OPENCODE_CONFIG_CONTENT`
  (`opencode/server-manager.ts:315-344,617-652`). Tested with OpenCode v1.14.46 and v2.0.10 (`docs/providers.md:100`).
  Only providers OpenCode reports as connected are offered; model ids `<providerID>/<modelID>`
  (`opencode-agent.ts:825,887-893`). OpenCode + Ollama setup: not found in Paseo docs.
- Provider overrides: `agents.providers.<id>` with `command`, `env`, `models`, `additionalModels`, `enabled`,
  custom entries via `extends` (claude, codex, copilot, opencode, pi, omp, acp) (`docs/custom-providers.md:50-75`); apply with `paseo reload`.
- MCP: agents' own configs by default; Paseo injects its own tools only with `daemon.mcp.injectIntoAgents`
  (default false) (`public-docs/mcp.md:13-20`).

## Plugin API
- Manifest `paseo-plugin.json`: `id`, `description`, `requirements.paseo` (semver range, required on 0.8+), `build`
  (`public-docs/plugins/reference.md:45-89`).
- Layout: `index.client.tsx` (runs in the app, including the phone), `index.server.ts` (daemon subprocess);
  other code only in `client/`, `server/`, `shared/` (`reference.md:91-127`).
- Workflow: `paseo plugin init <absolute dir>`, `npm install`, `npm run typecheck`, `paseo plugin install <absolute dir>`;
  enable plugins first (`pluginsEnabled`, default false, `config.ts:627`); `paseo plugin reload <id>`, `paseo plugin logs <id>`
  (`public-docs/plugins/index.md:26-38,211-287`).
- Packages: `@getpaseo/plugin` (`defineRpc`, `defineSettings`), `/client` (`usePaseo`, `useRpc`, `useWorkspace`, ...),
  `/client/ui`, `/client/react-native`, `/server` (`packages/plugin/package.json:10-56`).
- Client context: `addWorkspacePanel`, `addCommandCenterItem`, `addSettingsScreen`, ... (`packages/plugin/src/client/contracts.ts:87-124`);
  server: `handle`, `on`, `before`, `registerSettings`, ... handlers get `{ paseo }` (`packages/plugin/src/server/contracts.ts:9-43`).
- Server code runs in a separate Node process with the daemon user's full access: it can read files and run
  fixed commands (`reference.md:27,268-274,1791`); client code cannot import `node:*` (`reference.md:2089`).
  Pattern: RPC contract in `shared/` (`defineRpc`), `server.handle` in `index.server.ts`, `useRpc` in the panel
  (`reference.md:1721-1791`).
- Panels render React Native only (no DOM), styled from `theme.colors` / `layout.compact` (`reference.md:153-167,1020-1044`).
- Example: `plugin-examples/local-plugin` (`paseo-plugin.json`, `index.client.tsx`, `client/main.tsx`,
  `shared/increment.ts`, `server/increment.ts`, `index.server.ts`); settings example `plugin-examples/settings/`.
