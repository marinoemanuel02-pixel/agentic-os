# Coordinating coding agents on one Windows PC

**As of 1 October 2026.** Dates below are publication dates where available; “accessed” marks undated documentation and live repository counts. Stars show interest, not reliability. The strongest pattern for this setup is a shared task record, one working directory per writer, and a receipt that a coordinator verifies before accepting work.

## Coordination and open-source options

| Status | Project and mechanism | Fit and limits |
|---|---|---|
| Established building block | [Git worktrees](https://git-scm.com/docs/git-worktree) give each agent a separate checkout and branch (undated; accessed 2026-10-01). | Native Windows support. They isolate file edits, but agents still need task ownership and a controlled merge. |
| Substantial uptake | [Beads](https://github.com/gastownhall/beads) has **27.6k stars**. Its [coordination guide](https://github.com/gastownhall/beads/blob/main/docs/multi-agent/coordination.md) documents atomic `bd ready --claim --json`, assignees, dependencies, comments, and an exclusive merge slot (accessed 2026-10-01). | Good candidate for a durable task ledger. It explicitly has **no agent registry**: an assignee is a string, so “claimed” does not prove a session is alive. |
| Moderate uptake | [MCP Agent Mail](https://github.com/Dicklesworthstone/mcp_agent_mail), **2.2k stars**, supplies identities, inboxes, activity listings, and file reservations across Claude Code and Codex (accessed 2026-10-01). | Its leases are **advisory**: overlapping reservations can both be granted with conflicts reported. An optional commit guard adds enforcement. Local setup requires Python 3.14 and `uv`; its phone automation companion is commercial. |
| Larger, heavier system | [Gas Town](https://github.com/gastownhall/gastown), **18.2k stars**, combines agents, mail, worktrees, and merge coordination (accessed 2026-10-01). | Its README says the full tmux workflow on Windows needs WSL; native Windows is a minimal CLI setup. That is a poor first fit for this PC. |
| Experimental | [Succubus](https://github.com/enowdev/succubus), **18 stars**, claims a Windows capable board, presence, and file leases (accessed 2026-10-01). | Promising consolidation, with little adoption evidence yet. |

Claude’s [agent teams](https://code.claude.com/docs/en/agent-teams) have a shared task list and mailbox, but are experimental and confined to Claude sessions; [cross-session messaging](https://code.claude.com/docs/en/cross-session-messaging) likewise reaches other Claude sessions, including on native Windows, rather than Codex or Pi (both undated; accessed 2026-10-01). Neither is a cross-vendor presence system.

## Delegation and receipts

For **Claude → Codex**, the official open-source [Codex plugin for Claude Code](https://github.com/openai/codex-plugin-cc) is the clearest existing route: **33.7k stars**, with rescue, background status, stored results, cancellation, and session transfer. It uses the local Codex sign-in and consumes Codex quota (accessed 2026-10-01). For a symmetric wrapper that can call either vendor, the underlying CLIs expose `codex exec --json --output-schema …` and `claude -p --output-format json --json-schema …`; Claude’s JSON includes session, usage, and **estimated** cost metadata. Capture the process exit code separately. [Codex CLI reference](https://learn.chatgpt.com/docs/developer-commands?surface=cli), [Claude CLI reference](https://code.claude.com/docs/en/cli-reference), [Claude programmatic guide](https://code.claude.com/docs/en/headless) (undated; accessed 2026-10-01).

A wrapper should create a **task spec** with task ID, repo and base commit, worktree, allowed paths, acceptance checks, requested model, sandbox, deadline, and expected output schema. Its **receipt** should record session ID, actual model, start/end times, exit status, timeout, changed files and commit, test commands with exit codes, token usage or estimated cost, and any unverified claim. These fields are a proposed local contract, not an established standard. They directly address the missing run history and the delegate that wrote tests without executing them.

Preflight must query the **actual account**, not trust a saved model name: Codex app-server documents `model/list` for available models and efforts, and `account/rateLimits/read` for ChatGPT quota windows. The current [model documentation](https://learn.chatgpt.com/docs/models) says several older Codex model names retired during 2026. Check the delegate’s worktree for the required test executable and permissions before launch; an agent cannot repair a missing sandbox tool by promising to test later. [App-server documentation](https://learn.chatgpt.com/docs/app-server), [model documentation](https://learn.chatgpt.com/docs/models) (undated; accessed 2026-10-01). Retry transport or startup failures cautiously; a timed-out writer may already have changed files, so inspect its worktree before resuming.

**ACP and A2A solve different boundaries.** ACP connects a client to a coding-agent session; its [29 September 2026 compatibility matrix](https://github.com/agentclientprotocol/registry/blob/main/.protocol-matrix/latest.md) lists Claude, Codex, and Pi adapters. That makes it relevant if Paseo adopts one session interface, but it supplies no shared file lock or completion test. [A2A 1.0](https://github.com/a2aproject/A2A/blob/main/docs/specification.md) specifies interoperable agent tasks and artifacts; its [15 September 2026 roadmap](https://github.com/a2aproject/A2A/blob/main/docs/roadmap.md) still lists coding-harness CLI integration as upcoming. It is more infrastructure than three local CLIs need. The old `codex mcp-server` example is explicitly [archived and deprecated](https://developers.openai.com/cookbook/examples/codex/codex_mcp_agents_sdk/building_consistent_workflows_codex_cli_agents_sdk) (2025-10-01, archive notice accessed 2026-10-01).

## Teams, the local model, and memory

Use parallel workers for bounded, independent searches, reviews, tests, or edits in separate worktrees. Keep the lead’s context to requirements, decisions, and concise receipts; merge only after checking each diff and its tests. Both vendors warn that parallel writing raises conflicts and token use. Claude’s teams are experimental, and its docs say cost grows with active teammates; Codex recommends read-heavy work first. With entry-plan limits, cap cloud workers at **one per vendor**, adding a second only for a clearly independent task whose value exceeds the quota cost. [Claude teams](https://code.claude.com/docs/en/agent-teams), [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) (undated; accessed 2026-10-01).

Pi’s 4B model is a plausible **candidate generator** for routing among named options, tagging logs, and extracting short summaries with source lines. Performance is task and model dependent: a [12 January 2026 log-classification study](https://arxiv.org/abs/2601.07790) found large differences among small models; a [5 June 2026 judging study](https://arxiv.org/abs/2606.07810) found no single small judge dominated. Do not let Pi alone certify correctness, choose a risky fix, report a test as passed, or turn a confident `nar` score into fact. Verify its pick against repo evidence, a deterministic check, or an independent cloud reviewer; record “unverified” when none exists.

[AGENTS.md](https://agents.md/) is converging as repository instructions, and the [Agent Skills `SKILL.md` specification](https://agentskills.io/specification) defines portable, on-demand procedures (both undated; accessed 2026-10-01). Neither records live ownership. I found no comparable universal `HANDOFF.md` schema. Anthropic’s [24 March 2026 harness account](https://www.anthropic.com/engineering/harness-design-long-running-apps) supports structured artifacts carrying state and next steps between sessions; it does not imply that multiple sessions should rewrite one shared snapshot.

## Adopt first

1. **Claim work in Beads** with `bd ready --claim --json`; put the task ID in every delegation and commit. This gives scheduled and live sessions one ownership check.
2. **Give each writing session a branch and worktree.** Reserve the shared checkout for integration; use Beads’ merge slot for conflict-prone merges.
3. **Add a small local Claude/Codex CLI wrapper** using the task spec and receipt above. Require exit status and test evidence before marking a task complete.
4. **Preflight model, quota, tools, and sandbox.** Query Codex `model/list` and rate limits; check the selected test command in the delegate environment before spending quota.
5. **Stop concurrent writes to `HANDOFF.md`.** Have each session append a task-specific progress record; let one coordinator generate the top-level handoff after checking current claims.
6. **Use Agent Mail only if Beads comments prove insufficient.** Its inbox and presence are useful, but treat leases as warnings unless a guard actually blocks conflicting writes.
7. **Keep Pi advisory.** Ask for a ranked option with cited evidence, then verify the selected option before relaying it as a result.

These recommendations combine documented mechanisms; the proposed receipt and handoff conventions still need a local trial. Repository feature lists and star counts establish available options, not tested reliability on this machine.
